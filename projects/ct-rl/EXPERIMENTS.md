# CT-RL 实验协议与超参数

草稿给出了拟检验的问题、实验组和部分参数网格。以下是本实现锁定的训练与评价方案。训练检查点保存每次运行的完整配置，报告中的准确率由逐题预测重新计分。正式配置用于 Qwen2.5 实验，smoke 用随机初始化的小型 Qwen2 逐条执行相同的实验路径。

## 运行与交付

| 入口 | 用途 |
|---|---|
| `python -m ct_rl.paper --profile smoke --out runs/my-smoke` | 从数据、监督冷启动、策略更新和挖掘跑到选模、消融、公开适配和测试 |
| `python -m ct_rl.paper --profile paper --out runs/paper` | 使用固定版本的 Qwen2.5-1.5B 和 3B，读取完整 CT-Bench，准备正式公开集并执行完整矩阵 |
| `python -m ct_rl.public_data --profile paper --cache upstream --out data/public-paper` | 单独准备公开数据。整套实验可通过 `--public-data data/public-paper` 指定已准备好的文件 |
| `python -m ct_rl train --config configs/qwen1.5b.json --data data/paper --out runs/ltc --set method=ltc --set k=2` | 单独运行指定基线。所有基线共用检查点、恢复和推理入口 |
| `python -m pytest -q` | 检查执行器、信息隔离、采样重放、各目标的梯度、循环缓存、预算、划分和恢复 |
| `python -m scripts.audit_smoke runs/my-smoke` | 用保存的预测重算受控与公开得分，核验检查点摘要、选模、预算和反例池 |

安装命令为 `python -m pip install -e '.[public,test]'`。本目录的 [smoke 报告](reports/smoke/REPORT.md)、[逐种子结果](reports/smoke/controlled-results.json)、[逐公开任务结果](reports/smoke/public-results.json) 与实际运行对应。原始命令和运行环境写入运行目录或配置。所有配置和数据相同的中断任务可重新使用同一输出目录，合成训练在轮边界恢复，公开适配在已完成的检查点边界恢复。

## CT-RL 主方法

每次更新先取配对前缀的两侧。生成器仅见前缀，依次采样低维对角高斯动作 `U` 并映射成连续状态 `Z`。同一前缀的 K 条轨迹接受相同的 M 个后缀。读出器从固定说明、Z 和一个后缀新建上下文，程序执行答案决定回报。RLOO 使用同组其余轨迹的平均回报作为基线。策略更新时冻结映射，答案监督更新时切断 Z 的梯度。暖启动完成后冻结参考策略。每轮结束后对上一轮池项和新候选打分，下一轮使用新池。可选 GRPO 分支对已采样动作重放，并裁剪每一步的联合密度比。

| 参数 | 正式配置 | 矩阵 smoke | 依据 |
|---|---:|---:|---|
| 骨干 | Qwen2.5-1.5B-Instruct。规模验证用 3B | 1 层、宽 32。规模验证用 2 层、宽 48 | 主表保持骨干相同，第二规模检验按验证集选择的 3 个基线与主方法 |
| 精度与 Q/V LoRA 秩 | BF16，16 | FP32，4 | 冻结骨干，给生成器和读出器独立适配器。高斯参数与损失用 FP32 |
| 潜步数 T，动作维数 r | 8，64 | 2，8 | 正式中心点位于预设的容量网格内。接口的独立动作自由度受 T×r 限制 |
| 每批配对前缀数 P | 4 | 1 | 配对两侧同时入批，正式每步有 8 个前缀 |
| 每前缀轨迹 K，每轨迹后缀 M | 4，4 | 2，4 | 正式每个前缀用其余 3 条轨迹估计留一基线，4 个后缀平均后提供比单次判定更细的回报 |
| 续算微批 | 1.5B 为 4，3B 为 2 | 8 | 控制显存，核心策略和续算损失按有效样本数加权 |
| 冷启动更新 | 1,000 | 16 | 先建立可解码接口，使后续策略有机会收到可验证回报 |
| 等步数轮数 × 每轮更新 | 20 × 100 | 2 × 2 | 每轮固定课程。等 FLOPs 比较保留每轮更新数，并据实测计算量调整轮数 |
| 冷启动 / 策略 / 续算学习率 | 2e-4 / 5e-5 / 1e-4 | 4e-3 / 5e-4 / 2e-3 | 策略步长较小，限制相邻轮次的数据分布变化。随机初始化模型使用更高的监督步长 |
| AdamW | β₁=0.9，β₂=0.999，ε=1e-8，权重衰减 0 | 同左 | 常数学率。全局梯度范数上限 1 |
| KL 系数 β | 0.01 | 0.01 | RLOO 使用整条轨迹的采样对数比。改变 r 或 T 会影响 KL 大小，日志同时给出实际对数比 |
| 可选 GRPO | ε=0.2，2 个 epoch | 同左 | 同一批动作重放，使用解析高斯 KL。RLOO 每批只做一次策略更新 |
| 高斯标准差范围 | 0.05 至 1.50 | 同左 | 每坐标使用平滑有界参数化，避免联合对数密度出现退化方差 |
| 反例抽样比例 ρ | 0.5 | 0.5 | 有池项时保留一半基础分布抽样。池为空的前缀仍能参与训练 |
| 每轮搜索 | 128 对 × 最多 24 个新候选 × 2 次潜采样 | 2 对 × 最多 4 个新候选 × 1 次 | 每个候选在两侧评分，供失败率排序，同时重评已有池项 |
| 每个长度桶保留 | 2 个 | 1 个 | 避免池被同一操作长度占满 |
| 合成答案上限 | 16 token | 8 token | 短整数和结束符共用这项预算。CoT 在正式实验中使用 256 token，smoke 使用 128 token |
| 数据 / 训练 / 评估种子 | 120 / 31、41、51 / 1729 | 同左 | 分离实例划分、训练随机性和独立后缀。smoke 的公开适配和部分消融取首个训练种子 |

正式主方法每次策略更新评估 `2P × K × M = 128` 个“潜状态、后缀”组合，随后对重新生成的状态做 `2P × M = 32` 个答案监督。反例搜索、冷启动、执行器调用和配对探针分别记录。复跑基础示例另用两层宽 48、T=3、r=8、300 步冷启动及 3×12 次更新，结果单列在 [core-demo](reports/smoke/core-demo/evaluation.json)。

两个正式模型锁定到配置中的 Hugging Face 提交。模型文件由 Transformers 加载，检查点保存适配器与任务头。仓库没有 Git 元数据时，运行记录使用源码集合的 SHA-256 标识代码版本。[1.5B 配置](configs/qwen1.5b.json) · [3B 配置](configs/qwen3b.json) · [smoke 配置](configs/paper-smoke.json)

## 对照方法与额外监督

| 方法 | 本地训练目标 | 主要方法参数及适配选择 |
|---|---|---|
| Latent-SFT / Multi-Query SFT | 联合训练潜策略、映射与续算器的答案 NLL | 每前缀分别用 1 或 M 个后缀 |
| Static-Compress / Placeholder | 单次前缀编码后线性产生所有接口位置，或固定全零占位 | 匹配 T、r 和读出模块 |
| Single-Readout / Random-Suffix | 固定基础读出奖励，或基础分布上的随机后缀奖励 | 同一 RLOO、KL 与更新顺序 |
| Random-Separating / Hardness-Matched | 在长度桶内随机取区分后缀，或匹配失败率和操作数 | 难度匹配允许两侧标签相同，完整课程要求区分并发生模型错误 |
| Coconut† | 递归回馈前一步隐藏态，按课程逐步移除前缀执行轨迹的显式监督，再以完整潜状态答题 | 从 0 步逐渐增加到 T 步，余下轨迹在前缀侧预测。正式最后阶段只保留答案监督 |
| CODI† | 显式分支预测前缀推导与答案，学生预测答案并匹配教师各层答案前一位置的状态 | 教师目标停止梯度。Smooth-L1 按教师标准差缩放，各层等权，蒸馏权重 1 |
| Latent-GRPO† | 词表 top-k 软混合、一侧 Gumbel 扰动、有效样本组优势与 PPO 裁剪 | top-k=16，smoke 为 8。温度 1，扰动裁剪 [-1.5, 3] 后加 1.51。达到预算仍未结束的样本从优势统计中排除。正确轨迹只在首个潜步竞争 |
| SLPO† | MC dropout 采样潜状态，用独立 MC 前向的均值和各向同性方差估计轨迹分数。停止门与答案也获得回报 | dropout 0.1，4 次 MC，方差下限 1e-4，最短 3 步，smoke 为 1 步。最后一步强制停止，推理阈值 0.5。冷启动以所有能答对的停止长度的概率质量监督门控，权重 1 |
| LTC† | 每个固定问题/后缀采 K 个独立想法，每个想法采 A 个独立答案。想法与答案分别获得组优势，再做高分想法匹配 | K=2，正式 A=4，smoke A=2，两个温度均为 1，匹配权重 1。本实现使用保留 top-k 上的 Concrete 对数密度作为潜策略代理 |
| Direct / CoT | 完整文本前缀上的直接答案监督或显式推导加答案监督 | 在合成数据上，CoT 标签来自前缀执行轨迹。公开任务使用训练划分提供的步骤。串行成本评估复用合法的文本前缀缓存 |
| 循环 GRPO / RLTT / 循环 CT-RL | 同一个权重共享的因果栈按深度重复。前两者从最后一轮采样答案，分别优化末轮或每轮的答案 token。第三者用 CT-RL 的潜状态效用训练 | 正式循环深度 3，smoke 为 2。RLTT 的循环权重均匀，末轮参考分布 KL 为 0.01。此处采用 Qwen 权重共享栈作为循环骨干 |

† 方法在统一实验中使用相同的低维投影和严格的续算器输入。过程监督仅来自前缀，具体后缀在状态形成后交给续算器。公开任务还训练五种方法各自的原生推理路径，保留原始题面和内部潜向量。SLPO 原生读出实际停止长度，统一接口则补零到 T。五种方法与循环骨干均为项目内按原文机制编写的实现，统一采用本项目的骨干、适配器、优化器与数据预算。训练入口及公开模式分别由 `method`、`native_pretrain` 和 `--mode` 指定。[Coconut](https://arxiv.org/abs/2412.06769) · [CODI](https://arxiv.org/abs/2502.21074) · [Latent-GRPO](https://arxiv.org/abs/2604.27998) · [SLPO](https://arxiv.org/abs/2607.19691) · [LTC](https://arxiv.org/abs/2608.01593) · [RLTT](https://proceedings.mlr.press/v306/williams26b.html)

## 算力匹配、选模与消融

1. **合成训练。** 同一组先按相同训练轮数实测。令每个运行的训练总 FLOPs 为 C，最贵训练轮为 D，共同目标取组内最大值 max(C, 7D)。这样预算粒度通常足够容纳一整轮。匹配阶段按完整轮推进，达到共同目标的 93% 后检查，所有方法须落在共同目标的 ±10% 内。若有整轮越界，驱动提高共同目标后重新对齐。冷启动、策略与读出器、反例搜索全部计入。执行器 CPU 成本另计。
2. **规模选模。** 只对严格接口基线按等算力验证集的三种子平均 CT-Acc 排名。平局依次看 Pair-Both、All-Correct 和方法名。先写入选模记录，再打开测试集。3B 用相同的数据、相同的训练种子，独立匹配主方法与三个入选方法的训练算力。
3. **M 消融。** M 取 1、2、4、8。一组固定更新次数，另一组令每轮更新数与 M 成反比，使策略候选的后缀评估总次数精确相等。两组都记录实际 FLOPs。训练反例池使用相同的轮边界。
4. **容量与课程。** T 取 2、4、8、16，r 取 32、64、128，ρ 取 0、0.25、0.5、0.75，逐项改变，固定其他参数。另有等 FLOPs 的容量和课程组。附加 K=2、4、8，β=0，GRPO，以及关闭搜索的对照。
5. **状态干预。** 相同样本和随机种子下评估正常、移除 Z、全零、打乱潜步、在同基础读出的前缀对之间交换 Z，以及单独允许原始前缀 KV 的条件。仅正常的严格接口参与主排名。
6. **推理预算。** 批量 1 实测每查询 FLOPs、延迟、可见输出 token、缓存字节数与 CUDA 峰值。普通 M 个查询摊销一次前缀开销，额外 Pair-Both 探针另计。五个文献基线在确定性推理时逐步复用前缀 KV。smoke 在验证集上扫描 8、12、16 个输出 token，CoT 扫描 32、64、128，以实测成本的第 25 百分位附近、第 75 百分位附近和最高值确定三个共同档位。每个方法选取预算内验证准确率最高的配置，并记录独立 ID 测试上的实际开销及超支状态。没有可行配置的档位留空。复用曲线固定 M 为 1、4、8、16。
7. **误差与成本。** 主指标取任务族宏平均，三个种子给均值与样本标准差。95% 区间在各族内按底层配对实例重采样，正式运行 1,000 次。环境规模外推仅含图与规则，ID 差值按相同任务族构成计算。CPU 融合注意力沿用 PyTorch 融合注意力的矩阵乘法计数，包含前向与反向，乘加计 2 FLOPs。因果掩码按完整注意力矩阵估算，逐元素运算的覆盖取决于算子计数器。单卡 CUDA 小时用实测训练秒数换算。

## 公开适配

正式 GSM8K 从官方训练集固定留出 500 个题目组。PrOntoQA 使用官方生成器的五跳、虚构本体、零示例设置，种子 120，生成 10,000 项，预留 500 验证和 500 测试。ProsQA 读取 Coconut 发布的三个划分。MATH-500 的 500 题只用于测试 GSM8K 适配所得模型。数据准备保留官方测试题，避免相同题面出现在训练和验证/测试之间。固定上游版本、生成器文件与校验和见[数据准备代码](ct_rl/public_data.py)。[GSM8K](https://github.com/openai/grade-school-math) · [PrOntoQA](https://github.com/asaparov/prontoqa) · [ProsQA](https://github.com/facebookresearch/coconut) · [MATH-500](https://huggingface.co/datasets/HuggingFaceH4/MATH-500)

公开适配在每个数据集上单独匹配训练 FLOPs。正式每步取 2 题，先做 100 次监督更新，随后用 12 次训练更新估计成本，按 500 次后续更新制定共同目标。目标至少覆盖最昂贵校准步的 12 倍。各组从各自的来源权重训练到累计达到目标的 90%，核验 ±10% 界限后才发布检查点。若一个完整更新跨过整个允许区间，驱动提高该数据集的共同目标，重新核验所有对照并在验证集重新选模。恢复运行时用检查点摘要校验训练回执和评估结果。实际步数、学习率、逐步 FLOPs、解码预算和训练数据摘要见各组 `training.json`。smoke 使用 1 题/步、2 步监督冷启动和 2 步试测。

公开解码用贪心 Pass@1。正式直接与潜方法上限为 64 token，CoT 为 256 token。smoke 使用字节分词器，下表的上限包含 EOS。三个训练任务的 CoT 预算均可容纳 smoke 训练集中最长的完整示范。MATH-500 采用预设的数学答案预算，使用 GSM8K 适配权重。

| smoke 任务 | 直接或潜方法 | CoT |
|---|---:|---:|
| GSM8K | 16 | 320 |
| PrOntoQA | 8 | 320 |
| ProsQA | 32 | 192 |
| MATH-500 | 64 | 320 |

GSM8K 接受整数、小数和分数，千分位逗号必须按三位分组。MATH-500 使用符号等价判定，逻辑题使用标准化匹配。报告区分解码耗尽、缺少最终答案、无法解析和解析成功。每个公开任务保存验证集并列第一的方法清单。并列时按名称选一个基线，与 CT-RL 分别训练零合成预训练版本。[Math-Verify](https://github.com/huggingface/Math-Verify)

正式公开划分也已实际生成并校验。GSM8K 的训练、验证、测试分别为 6,973、500、1,319 题，PrOntoQA 为 9,000、500、500 题，ProsQA 为 17,886、300、500 题，MATH-500 测试为 500 题。此仓库提供固定生成器、上游校验和及逐题划分标识，可用前面的 `public_data` 命令重建全文。正式推理基准使用以上全量题库，smoke 测试使用单独的小样本划分。[正式数据清单](data/public-paper-manifest.json) · [逐题划分标识](data/public-paper-split-ids.json.gz)
